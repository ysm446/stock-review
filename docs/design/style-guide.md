# UI スタイルガイド

このアプリ（Electron renderer）の見た目に関する唯一の基準。**UI に変更を加えるときは必ずこのファイルに従う**。
ここに書かれていない見た目の判断が必要になったら、まず既存の似た部品を探して合わせ、新しいルールを決めたらこのファイルに追記する。

- 対象: `src/styles.css`、`src/index.html`、`src/setup.html`、`src/*.js` の DOM 生成・canvas 描画。
- CSS は `src/styles.css` の 1 ファイルに集約する。新しい CSS ファイルや `<style>` タグ、インラインスタイルは原則追加しない（動的な位置・幅・高さなど、値が実行時にしか決まらないものだけ JS から `style` で設定してよい）。
- 文言は日本語。

---

## 1. 原則

1. **基準は「チャート・ニュース・データ表示」。** 迷ったら、株価チャート周り・マーケットのニュースカード / AI まとめ・保有テーブル・指標カード・ノートカードの見た目に合わせる。**これらがこのアプリの標準であり、他はここへ寄せる。**
   - 逆向きに揃えない。つまり「チャットがこうだから他も大きくする」ではなく、**チャットをデータ側に合わせる**。
   - チャット（チャットビュー・銘柄チャット・ドキュメント編集）を読み物扱いして独自の大きなスケールを与えない。同じ画面に本文サイズが 2 種類存在する状態を作らない。
2. **色は必ず CSS 変数（トークン）経由で指定する。** 生の hex / rgb を CSS に直接書かない。テーマ切り替えが壊れる。
3. **一貫性 > 局所最適。** 「この画面だけ少し大きく」を積み重ねない。似た役割の要素は同じサイズ・同じ余白にする。
4. **落ち着いた暗色ベース、彩度は情報にだけ使う。** 面や枠は無彩色〜低彩度。鮮やかな色は損益・状態・チャート系列など「意味のある情報」に限る。
5. **密度を保つ。** 数値を並べて比較する道具なので、余白よりも一覧性を優先する。フォントもコントロールも小さめ・低い。

### 基準として参照する実装

新しい画面・部品を作るときは、まずこれらを見て合わせる。

| 種別 | 参照する実装 |
| --- | --- |
| カード（敷き詰め） | `.market-news-item`（ニュース）、`.market-summary-block`（AI まとめ）、`.review-note-card`（ノート） |
| 本文（読ませるテキスト） | `.market-summary-block-body`、`.review-note-card-body` = `0.88rem` / 行間 `1.65` |
| 数値の一覧 | `.holdings-table`、`.watchlist-table` |
| チャート周りの操作 | レビュー / マーケットのチャート操作ボタン・メニュー（28px / `0.7rem`） |
| パネル | `.panel` + `.panel-head` |

## 2. 色

### 2.1 テーマの仕組み

- `:root` = **ダーク**（デフォルト）。`:root[data-theme="navy"]` = **ネイビー**。定義は `src/styles.css` の先頭。
- 適用は `src/theme.js`（非モジュール script、`<head>` でスタイルシートより前に読み込み、FOUC 防止）。API は `window.StockReviewTheme`（`get` / `set`、localStorage キー `stock-review.theme`、`stock-review:theme` イベント発火）。
- **テーマを増やすときは `:root[data-theme="xxx"]` に同じ変数群をすべて上書きし、`theme.js` の `THEMES` に追加するだけ**で済む状態を保つ。そのため新しい色が必要になったら、値を直書きせず**変数を新設して全テーマに定義する**。

### 2.2 トークン一覧

| 用途 | 変数 | 使いどころ |
| --- | --- | --- |
| サーフェス | `--bg` | 画面の地。`body` |
| | `--bg-alt` | 入力欄の背景 |
| | `--panel` | パネル・カード・統計カードの面 |
| | `--panel-soft` | 一段沈んだ面（サイドバー、ステータスバー、トグルの受け皿、`.review-card`） |
| | `--panel-raised` | 一段浮いた面（チップ、小さいツールチップ） |
| | `--line` | 標準の枠線・区切り |
| | `--line-soft` | 弱い区切り（テーブルの行罫線） |
| テキスト | `--text` | 本文 |
| | `--text-strong` | 見出し・強調（カード見出し、アクセントボタン） |
| | `--text-soft` | やや弱い本文（チップのラベル等） |
| | `--muted` | ラベル・補助説明・非アクティブ・`th` |
| コントロール | `--control-bg` / `--control-bg-hover` / `--control-bg-active` | ボタン・セレクトの通常 / hover / 選択中 |
| | `--control-border` | フォーカス時の枠、フォーカスリング |
| | `--control-border-strong` | アクセントボタンの枠 |
| 意味色 | `--pos` / `--pos-soft` | プラス（強 / テーブル内など弱） |
| | `--neg` / `--neg-soft` | マイナス（強 / 弱） |
| | `--danger` | 破壊的操作（削除ボタン） |
| | `--link` | リンク、実行中インジケーター、`.stat-card-accent` |
| | `--warn` / `--warn-strong` | 注意・特殊状態（過去表示など） |
| | `--accent` / `--accent-soft` | 選択枠・リング |
| 重ね物 | `--topbar-bg` / `--menu-bg` / `--tooltip-bg` / `--modal-bg` / `--modal-border` / `--overlay` | 半透明のバー・メニュー・ツールチップ・モーダル・背面覆い |
| スクロールバー | `--scrollbar-thumb` / `--scrollbar-thumb-hover` | カスタムスクロールバー |

### 2.3 意味色の使い分け（重要）

- **損益・増減は `--pos`（プラス＝緑系）/ `--neg`（マイナス＝赤系）。** 数値そのものやサマリー値には `--pos` / `--neg`、テーブルのセルなど面積が広く並ぶ場所は目に刺さらない `--pos-soft` / `--neg-soft` を使う。
- 状態クラスは `.is-positive` / `.is-negative` に統一する（新しい独自クラス名を作らない）。
- **ローソク足だけは日本市場の慣習に従い「上昇＝赤 / 下落＝緑」**（`CANDLE_UP_COLOR` / `CANDLE_DOWN_COLOR`）。ポートフォリオの損益色とは意味が逆になるが、これは意図的。ローソク足以外にこの反転を持ち込まない。
- 破壊的操作の文字色・枠は `--danger`。ただし背景まで赤くしない（削除ボタンは背景 transparent + 文字 `--danger`）。

### 2.4 やってはいけないこと

- CSS に `#4ade80` のような生の色を書く（`rgba(255,255,255,0.03)` 等のごく薄い汎用オーバーレイのみ例外）。
- 意味のない色で情報を区別する（例: 単に見分けるためだけに緑と赤を使う）。
- テーマ変数を片方のテーマだけに定義する。

## 3. タイポグラフィ

- **フォント**: `"Segoe UI", "Yu Gothic UI", sans-serif`。`html, body` の 1 箇所だけで指定し、他では `font-family` を指定しない。等幅は使わない（数値は右揃え＋桁で揃える）。
- **ルートサイズ**: `14px`。以降のサイズは `rem` で書く（`px` 指定はアイコン・線幅など実寸が要る箇所だけ）。

### 3.1 サイズスケール

新しい要素には、下の表から**最も近い役割の行を選んで使う**。表にない値を足さない。

| rem | 用途 |
| --- | --- |
| `0.7rem` | 極小の補助（チャート内ラベル、ツールチップ本文、チャート操作ボタン） |
| `0.72rem` | ステータスバー、`.eyebrow` / `.panel-kicker` |
| `0.74rem` | カードの補足（`.stat-sub`、`.panel-hint`） |
| `0.76rem` | 小ラベル（`.stat-label`、チップ） |
| `0.78rem` | 既定の小テキスト（トグル、設定ラベル、行メニュー）——**最頻値** |
| `0.82rem` | テーブルヘッダ、やや小さい本文 |
| `0.84rem` | フォーム部品・ボタン（`input` / `select` / `textarea` / `.ghost-button` / `.accent-button`） |
| `0.88rem` | **本文の基準**（テーブル本文、ノートカード本文、AI まとめ本文、計算値セル、**チャット本文・チャット入力欄**） |
| `0.92〜0.95rem` | パネル内の小見出し |
| `1rem` | モーダル見出し、本文中の最大見出し（h1） |
| `1.25rem` | 統計カードの数値 |
| `1.35rem` | チャートの現在値（`.review-chart-quote strong`） |
| `clamp(1.35rem, 2.4vw, 1.75rem)` | 画面タイトル（`.hero h1`） |

### 本文中の見出し（Markdown 描画）

チャット回答・ノートカード・AI まとめはいずれも Markdown を描画する。**本文 `0.88rem` に対して見出しは以下の 3 段のみ**とし、領域ごとに別スケールを作らない。

| | サイズ |
| --- | --- |
| h1 | `1rem` |
| h2 | `0.94rem` |
| h3 | `0.9rem` |

> 以前はチャットだけが本文 `1.16rem`・見出し `1.24〜1.48rem` の独自スケールを持ち、銘柄チャットにはさらに個別の上書きがあった。**2026-08-11 に上記へ統一し、個別上書きは削除した。** 同種の上書きを復活させないこと。
>
> チャット用 CSS（`.chat-message-text` 系）は詳細度が高く、その中に置いたデータ表示のサイズ指定を上書きしてしまうことがある。負ける場合は親カードを付けたセレクタ（例: `.review-note-card .review-note-card-body`）で指定する。

### 3.2 ウェイト・行間

- ウェイトは **400 / 600 / 700** の 3 段だけ。500 は使わない（既存の残りは順次 600 へ寄せる）。
  - 600: `th`、強調値、設定値、アクセントボタン。
  - 700: 統計カードの数値、画面タイトル、ツールチップの主要数値。
- 行間: 本文 `1.5`、読み物（ノート・AI まとめ）`1.65`、極小ラベル `1.45`。
- 大文字化（`text-transform: uppercase`）は使わない。`letter-spacing` はキッカー（`0.04em`）以外に付けない。

## 4. 余白・サイズ・形

### 4.1 スペーシング

**4px グリッド**。使う値は `2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 px`。それ以外（7px, 9px, 11px…）を新しく足さない。

| 値 | 用途 |
| --- | --- |
| `2〜4px` | アイコンとテキスト、密なチップ内 |
| `6〜8px` | 部品内部の要素間、ボタン群 |
| `10〜12px` | カード内のブロック間、グリッドの gap、パネルヘッダの gap |
| `14〜16px` | パネル間、レイアウトグリッドの gap、セクション下マージン |
| `20〜24px` | 画面外周（`.main-panel` は `20px`）、モーダル外周 |

- パネル / カードの内側は `14px`（例外的に情報密度が低い設定系は `16px`）。
- テーブルセルは `10px 8px`。
- 小さいコントロールの左右パディングは `10〜12px`。

### 4.2 角丸

| 値 | 用途 |
| --- | --- |
| `6px` | 極小の四角い部品（行メニューのトリガ、小ツールチップ） |
| `8px` | **標準**。ボタン、入力、チップ状でないタブ、小カード |
| `10px` | パネル・統計カード・ナビボタン |
| `12px` | モーダル |
| `999px` | ピル（トグル群、チップ、スクロールバー、ドラッグハンドル、インジケーター） |
| `50%` | 円形ドット |

### 4.3 コントロールの高さ

| 高さ | 用途 |
| --- | --- |
| `22px` | アイコンだけの極小ボタン |
| `26px` | チップ、トグルボタン、行メニュートリガ |
| `28px` | チャート操作ボタン（フォント `0.7rem`） |
| `30px` | 密なテーブル内ボタン |
| `34px` | **標準ボタン / セレクト**（`.ghost-button` / `.accent-button`） |
| `40px` | チャットの送信など主要アクション |
| `44px` | サイドバーのナビボタン |

同じ行に並ぶコントロールは高さとフォントサイズを必ず揃える。

### 4.4 レイアウト定数

- サイドバー幅 `60px`（`.model-topbar` / `.app-body` / `.app-statusbar` が `margin-left: 60px`）、トップバー高さ `56px`、ステータスバー高さ `32px`。
- `.app-body` は横並びの flex で、左が画面本体 `.main-panel`、右が常設チャット `.chat-dock`（既定幅 `420px`、ドラッグで `320px`〜`min(900px, 画面幅の60%)`、背景 `--panel-soft`、左罫線 `--line`）。開閉ボタンはトップバー右端（`.ghost-button` と同寸の 34px）。
- 画面本体 `.main-panel` はパディング `20px`、縦スクロールはここが担当する。
- グリッドの gap は `16px`（レイアウト） / `10px`（カードの敷き詰め）。
- 敷き詰めグリッドは `repeat(auto-fill, minmax(250px, 1fr))`（カード）/ `repeat(auto-fit, minmax(140px, 1fr))`（統計カード）。
- ブレークポイント: `max-width: 1500px`（ダッシュボードの固定高を解除）、`max-width: 1180px`。要素幅に応じた分岐は `@container`（例: `min-width: 860px` で 2→3 カラム）を優先する。
- 標準の画面サイズは **1920×1080**（コンテンツ領域）。この幅で最良に見えるよう調整する。

### 4.5 影

影は「浮いている物」だけに付ける。面（パネル・カード・テーブル）には**付けない**。

- モーダル: `0 20px 60px rgba(0, 0, 0, 0.45)`
- ポップオーバー / メニュー / ドロップダウン: `0 12px 28px rgba(0, 0, 0, 0.28)` 前後
- フォーカスリング: `0 0 0 1px var(--control-border)`

## 5. 部品

### 5.1 ボタン

| 種類 | 見た目 |
| --- | --- |
| `.ghost-button` | 標準。高さ 34px / 角丸 8px / 枠 `--line` / 背景 `--control-bg` / 文字 `--text` / `0.84rem` |
| `.accent-button` | 主要アクション。同寸法で背景 `--control-bg-active` / 枠 `--control-border-strong` / 文字 `--text-strong` / `font-weight: 600` |
| `.icon-remove` | 削除。34×34 / 枠 `--line` / 背景 transparent / 文字 `--danger` |
| `.nav-button` | サイドバー。44px 高 / 角丸 10px / 通常は透明＋`--muted`、hover・`.is-active` で `--panel` ＋ `--line` ＋ `--text` |

- **1 つの操作群にアクセントボタンは 1 つまで。**
- 状態は `background` / `color` / `border-color` の変化で表す。移動やスケールは使わない。
- 無効時は `opacity: 0.5` ＋ `cursor: default`。

### 5.2 入力（`input` / `textarea` / `select`）

- 幅 100% / 枠 `--line` / 角丸 8px / パディング `8px 10px` / 背景 `--bg-alt` / `0.84rem`。
- フォーカス: `outline: none` ＋ 枠を `--control-border` ＋ `box-shadow: 0 0 0 1px var(--control-border)`。**OS 既定のフォーカスリングは出さない。**
- ボタンは `:focus { outline: none }`、`:focus-visible` のときだけ `outline: 2px solid var(--control-border); outline-offset: 1px`（キーボード操作の可視性は必ず残す）。
- インライン編集（現金カード等）は枠なし＋下線 1 本、フォントは `inherit`。

### 5.3 パネル / カード

- `.panel`・`.stat-card`: 枠 `--line` / 角丸 10px / 背景 `--panel` / パディング 14px。
- `.panel-head`: `flex`・`space-between`・`align-items: center`・`gap: 12px`・`margin-bottom: 12px`。左に `h2`、右に `.panel-actions`。
- 補足は `.panel-hint`（`--muted` / `0.74rem`）、上部の小ラベルは `.panel-kicker` / `.eyebrow`。
- 沈んだカード（`.review-card`）は背景 `--panel-soft`。
- カードを入れ子にしない。**枠は 1 段だけ**（グリッドで敷き詰めるカード群に、さらに外枠パネルを被せない）。

### 5.4 テーブル

- `width: 100%` / `border-collapse: collapse`、本文 `0.88rem`。
- `th`: `--muted` / `600` / `0.82rem` / 左揃え。
- `td`: パディング `10px 8px`、下罫線 `--line-soft` のみ（縦罫線・ゼブラは使わない）。
- **数値列は右揃え**、銘柄名など文字列は左揃え。計算値は `.computed-cell`（`600` / `0.88rem`）。
- 列幅は `table-layout: fixed` ＋ `nth-child` で明示する。
- 行の hover / ドラッグ状態は `rgba(255,255,255,0.03)` 程度のごく薄い背景で表す。

**データテーブルと本文中のテーブルを区別する。**

| | 幅 |
| --- | --- |
| データテーブル（保有・ウォッチリスト・指標） | グローバルの `table { width: 100% }` に従い全幅 |
| 本文中の Markdown テーブル（チャット回答など） | `width: auto` ＋ `max-width: 100%` = **内容の幅に合わせる** |

本文中のテーブルは列が少ないことが多く、全幅に引き伸ばすと列が間延びして読みにくい。グローバル指定を打ち消す `width: auto` を明示すること。

### 5.5 タブ・トグル・チップ

- **セグメント型トグル**（`.view-toggle`）: 受け皿は `--panel-soft` ＋ 枠 `--line` ＋ 角丸 999px ＋ padding 3px。中のボタンは高さ 26px / 角丸 999px / 通常 `--muted` / `.is-active` で `--control-bg-hover` ＋ `--text`。
- **縦タブ**（設定モーダル）: 角丸 8px / padding `8px 10px` / 通常は透明＋`--muted`、hover・`.is-active` で `--panel` ＋ `--line` ＋ `--text`。
- **チップ**（候補質問など）: 高さ 26px / 角丸 999px / 背景 `--panel-raised` / 枠 `--line` / 文字 `--text-soft` / `0.76rem`。
- 選択状態は常に `.is-active`。独自の選択クラスを作らない。

### 5.6 モーダル

- 背面: `position: fixed; inset: 0`・`--overlay`・`backdrop-filter: blur(3px)`・padding 24px・`display: grid; place-items: center`。
- カード: `width: min(100%, 420px)`（設定など幅広は 560px）・角丸 12px・背景 `--modal-bg`・枠 `--modal-border`・影あり。
- ヘッダ: padding `14px 16px`・下罫線 `--line`・`h2` は `1rem`。
- 開閉は `.is-hidden`（`display: none`）で切り替える。

### 5.7 メニュー・ツールチップ

- ポップオーバー: 背景 `--menu-bg`（半透明）/ 枠 `--line` / 角丸 8px / 影。
- ツールチップ: 背景 `--tooltip-bg` または `--panel-raised`、`0.7rem`、`pointer-events: none`。
- どちらも hover ではなくクリックで開くものは、外側クリック・Esc・スクロール・リサイズで閉じる。

### 5.8 ステータス表示

- ステータスバーは `--panel-soft` ＋ `--muted` ＋ `0.72rem`、7px の丸ドットで状態を示す（既定 `--muted` / 実行中 `--link` / 成功 `--pos` / 失敗 `--neg`）。
- 進捗バーは高さ 6px 前後・角丸 999px・受け皿 `--panel-soft`。不定進捗はパルスアニメーション。

### 5.9 チャット（チャットビュー / 銘柄チャット / ドキュメント編集）

チャットは**独立したデザインではなく、データ表示側に従属する**（§1）。以下は他の部品と同じ値であることが要件。

- 本文・入力欄: `0.88rem` / 行間 `1.65`。見出しは §3.1 の 3 段。
- 吹き出し: padding `10px 14px`・角丸 8px（他のカードと同じ）。ユーザー側のみ背景 `--accent`＋右下角 4px、アシスタント側は背景・枠なし。

## 8. モーション

- **短く・控えめに。** duration は `100 / 120 / 140ms`、easing は `ease`。ビュー切替の `fade-up` だけ `320ms`。
- アニメーションしてよいプロパティ: `background` / `color` / `border-color` / `opacity` / `width`。**`transform` での拡大縮小や跳ねる動きは使わない。**
- ローディングのパルスは `1.0〜1.2s ease-in-out infinite`。

## 9. チャート（canvas）の配色

canvas は CSS 変数が効かないため、色は JS 定数に集約する。**描画関数の中に色リテラルを直接書かない。**

- 移動平均線 `MA_COLORS`: 25=`#f59e0b` / 50=`#06b6d4` / 75=`#a78bfa` / 200=`#ec4899`（`src/candlestick-chart.js`）。
- 信用残 `MARGIN_COLORS`: 買い残=`#f97316` / 売り残=`#38bdf8`。
- ローソク足: 上昇=`#ef4444` / 下落=`#22c55e`（**§2.3 参照。ここだけ赤＝上昇**）。
- 保有割合の系列色: 色相 `[210, 330, 180, 270]` × 明度 4 段（`hsl()` で生成）。セクター別配色は `SECTOR_COLOR_HUES` のキー色相＋セクター内グラデーション、セクター不明はグレースケール（`hsl(220, 8%, L%)`）にフォールバック。現金は `hsl(150, 32%, 50%)`。
- チャートのテキスト・グリッドは低彩度のグレー（`#9ca3af` / `#94a3b8` 系）。
- 系列色を増やすときは既存の色相セットを拡張する形にし、単発の新色を差し込まない。

> **既知の制約**: canvas の色はハードコードでテーマに追従しない。将来 `getComputedStyle` でトークンを読む形へ移行する予定（`docs/plan/progress.md` 参照）。それまでは、新規のチャート色も上記定数ファイルに集約しておく。

## 12. 既知の逸脱（見つけたら直す方向）

このガイドは現状のコードから起こしたもので、以下はまだ揃っていない。**新しいコードでは繰り返さない**こと。既存箇所は触るついでに寄せる。

1. フォントサイズが表にない値（`0.6 / 0.62 / 0.65 / 0.66 / 0.68 / 0.75 / 0.8 / 0.85 / 0.86 / 0.95 / 0.98 / 1.4rem` など）で散らばっている。→ §3.1 の最寄りの値へ寄せる。
   - うち `0.62rem`（開閉トグルの三角）・`0.75rem`（ツリーの小アイコンボタン）は文字ではなくアイコン相当のため当面据え置き。
   - 初回セットアップ画面（`.setup-title` `1.4rem` / `.setup-lead` `1rem`）は独立した全画面カードのため許容。
2. 4px グリッドから外れた余白（`7px`・`9px`・`11px`・`3px`）が一部にある。
3. 角丸 `4 / 7 / 9 / 14px` が散発的に使われている。→ §4.2 の値へ。
4. `font-weight: 500` が数箇所残っている。→ 600 へ。
5. canvas チャートの色がテーマ非追従（§9 の制約）。
6. transition の duration に `100 / 120 / 140 / 200 / 300ms / 0.15s` が混在。→ `120ms ease` を既定に寄せる。
